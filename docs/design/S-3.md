# Design doc S-3: Ranked applicants with the "Does not meet minimum" flag

**Story S-3.** As an HR recruiter, I want all applicants for a posting listed by fit score, with anyone missing a required skill flagged "Does not meet minimum" and never ranked above an applicant who meets them all, so that I review qualified candidates first instead of reading every resume.

**Status:** designed and tested only. Not built in Milestone 1. Its tests are skipped with their AC IDs.

## 1. Problem
Hiring managers lose evenings screening resumes. In one batch, about 3 of 60 had the core experience (E-11). Keyword-and-years screening produced a shortlist the hiring manager mostly rejected (E-12). Mapping experience to requirements is the slowest step (E-13). Hiring managers still move ahead with a candidate who falls short on non-technical skills, so the system flags applicants and never removes them (E-14).

## 2. Scope
- Given a posting's required skills and each applicant's skills and fit score, return every applicant in ranked order, each with a minimum flag and their missing required skills.
- Expose that ranked list over HTTP for a posting.

## 3. Non-goals
- No fit-score calculation. Scores arrive as input from S-4.
- No automatic rejection. Ranking never changes an application's stage, and no one is left out of the list (proposal non-goal; E-14).
- No recruiter override of the flag (Q-5).
- No synonym matching (Q-9).

## 4. Interface
Domain, `jobsboard.ranking`:
- `@dataclass(frozen=True) class Candidate`: `application_id: str`, `skills: frozenset[str]`, `fit_score: int`.
- `@dataclass(frozen=True) class RankedEntry`: `application_id: str`, `fit_score: int`, `meets_minimum: bool`, `flag: str | None`, `missing_required: tuple[str, ...]`.
- `def rank_applicants(required_skills: frozenset[str], candidates: list[Candidate]) -> list[RankedEntry]`. Raises `InvalidFitScore(application_id, fit_score)` if a score is outside 0–100, and `DuplicateApplication(application_id)` if an ID appears twice.

HTTP:
- `GET /postings/{posting_id}/ranked` returns 200 with `[{"application_id", "fit_score", "meets_minimum", "flag", "missing_required"}]`, or 404 `{"detail": {"error": "posting_not_found"}}`.

## 5. Data
- `required_skills: frozenset[str]`, which may be empty. Each skill is a non-empty string.
- `skills: frozenset[str]`. Each skill is a non-empty string.
- `fit_score: int`, from 0 to 100 inclusive.
- `flag: "Does not meet minimum"` or `None`.
- `missing_required: tuple[str, ...]`, the required skills not matched, sorted alphabetically, using the posting's spelling.

## 6. Rules
- **R1 (meets minimum).** `meets_minimum` is true exactly when `missing_required` is empty. Skills match when they are equal after trimming whitespace and ignoring case (A-5).
- **R2 (flag).** `flag == "Does not meet minimum"` exactly when `meets_minimum` is false. Otherwise `flag` is `None`.
- **R3 (invariant, ranking).** No entry with `meets_minimum` false appears before any entry with `meets_minimum` true.
- **R4 (order within a group).** Within each group (meets minimum, and not), `fit_score` never increases from one entry to the next.
- **R5 (no one dropped).** The output has the same application IDs as the input, each exactly once.
- **R6 (no side effects).** Ranking does not change any application's stage. The S-1 pipeline response is identical before and after.

## 7. Edge cases
- A posting with no required skills. Everyone meets the minimum, and the list is ordered by score alone.
- Every applicant flagged. The list is still ordered by score, and all are flagged.
- A flagged applicant with score 100 and an unflagged applicant with score 0. The unflagged applicant comes first (R3).
- Skill case and spacing differ (" java " vs "Java"). They match under R1.
- An empty candidate list returns an empty list. Scores of -1 or 101 raise `InvalidFitScore`.

## 8. Decisions and open questions
**Decisions**
- D1. Matching is exact after trimming and ignoring case. There are no synonyms (A-5).
- D2. The flag text is exactly `Does not meet minimum`.
- D3. Flagged applicants stay in the list and keep their stage. Ranking never rejects anyone.
- D4. Out-of-range scores are rejected with `InvalidFitScore`, not clamped.

**Open questions**
- OQ-1 (Q-6). How are applicants with equal fit scores ordered? Do not build anything that depends on this. Stop and ask.
- OQ-2 (Q-5). Can a recruiter override the flag, and where does an overridden applicant rank? Do not build anything that depends on this. Stop and ask.
- OQ-3 (Q-9). Do skill synonyms (for example "Postgres" for "PostgreSQL") count as a match? Do not build anything that depends on this. Stop and ask.
